## Safe source/history import strategy

1. Preserve recorded commit IDs, original repository identity/branch and license notices as provenance. Current root checkout has no committed source import; the three source folders are nested clean Git repositories.
2. Never import nested `.git`, dotenv/credential files, node_modules/.venv, developer build products, logs, caches, DB clusters/dumps, uploads or generated outputs. UI tracks `.env.local`; API tracks `.env.local` and `.env.production`. Their contents were deliberately not read. Ignoring a path does not remove it from Git history.
3. Review the ignored local migration series and models, establish schema equivalence in a disposable cluster and deliberately add approved migrations/seeds. Retain hashes of original local artifacts; do not regenerate/replace history solely to make a new install run.
4. Under #5, use an approved sanitized source snapshot or sanitized rewritten history after secret scanning all refs/objects and confirming redistribution permission. Keep a private provenance mapping to original commits; preserve attribution. Do not push unsanitized history or claim a clean secret scan from this audit.
5. Build a credential-name-only example config. Local bootstrap generates installation-owned secrets and role/config seeds; external providers are optional user-owned configurations. Preserve separate website build/deployment profiles and test against this full matrix.

No credentials, data records, provider transactions, deploys, schema changes or source/history imports were performed by this audit.
