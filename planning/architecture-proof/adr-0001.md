# ADR 0001 — Retain Next/Express; reject the unoptimized payload against current budgets

Date: 2026-11-10. Status: **Proposed / evidence incomplete**, not an accepted production architecture. Parent #4 remains in progress; no acceptance criterion is marked complete by this ADR draft.

**2026-11-11 user amendment:** [local speech-to-text removed from v1; PostgreSQL retained; pgvector deferred](../v1-scope-2026-11-11.md). This supersedes the extension and Whisper requirements below, not the old measured text-model footprint. The smaller text-embedding experiment still serves retained PDF/YouTube references. Extension-free storage/ranking requires compatibility proof. No existing measurement or acceptance is converted into a pass.

## Context

**2026-11-11 evidence addendum:** [PostgreSQL-only native proof](postgres-only/report.md) resolves the original archive acquisition blocker with EDB 17.11 revision 5 and verifies isolated SQL writes/restart/backup/restore without pgvector. The reviewed fresh-cluster candidate requires a duplicate-index guard, Anki index/FK ordering repair, finite array storage and a missing-feedback supplement. These are not adopted production migrations. This supersedes the earlier PostgreSQL acquisition status below, while preserving its historical record; no ADR acceptance or complete P3 pass follows.

[Approved v1 contract](../platform-support.md) requires every existing workflow, local authoritative data, genuine deliberate providers, self-contained native installers on Windows/macOS/Linux, ≤250 MB installer and ≤750 MB installed application. All runtimes/models/native processing resources must count. The contract is a target, not compatibility evidence. #41 payments are explicitly deferred; classroom v1 is LAN/user-owned host.

[First native Windows experiments](report.md) show retained Next standalone can serve sampled locale/dynamic routes under Electron utilityProcess with a guarded packaged module directory. Compiled Express reaches real initialization but cannot reach HTTP readiness without lazy optional-provider fixes. CPU FastAPI produces real 384-dimensional vectors offline from a supplied snapshot, while the known batch schema defect remains. Native PostgreSQL acquisition returned HTTP 403; no cluster was initialized. No macOS/Linux native execution or installer exists.

Three necessary files in the observed Windows candidate alone total **983,130,048 bytes**: FP32 model weights, actually loaded torch CPU DLL and executed Electron binary. That exceeds the installed budget before every other asset. The tested model-only LZMA2 stream is 410,574,192 bytes; no complete NSIS size is asserted. This exact unoptimized payload cannot satisfy the approved installed-size contract by pruning unrelated development files.

## Proposed direction, with unresolved gates

1. Preserve the whole Next/Express UI/business backend and website source. Electron utilityProcess is a viable Windows component execution path; it is not yet proven for the complete stack or every required OS/CPU/ABI.
2. Do **not** adopt/distribute the measured unoptimized FP32/PyTorch payload as budget compliant. Evaluate a smaller CPU execution backend/quantized representation of the same multilingual model behind the existing FastAPI/384-vector contracts, with en/vi quality, retrieval, numerical behavior, latency and native resource evidence. No model/quality degradation is silently authorized.
3. Keep PostgreSQL/pgvector as candidate pending native binaries, reviewed migration/extension/seed/repository/vector contracts and persistence proof. Do not replace it with SQLite on footprint assumptions.
4. Prove native document conversion, URL→PDF, whisper.cpp/tiny/FFmpeg and fonts; evaluate sharing Electron Chromium only through real capability/security tests. Their unknown footprint cannot be treated as zero or optional feature deletion.
5. Implement scoped measured startup fixes in the appropriate shared profile/work before integrated proof: lazy mail/PayOS/Redis replacement, trustworthy readiness, `sharp`, SSR browser globals, CSP/loopback/session boundaries. Keep payment execution deferred.
6. Run linked #45/#46/#47 native installer baselines and P7 full process/resource/data lifecycle tests. An accepted decision requires actual evidence; host access, cross-compilation or source inventories do not satisfy native acceptance.

## Alternatives and consequences

- **Ship the current measured payload unchanged:** rejected under the 750 MB installed target; other gates remain unsatisfied.
- **Optimize CPU model/runtime and shared browser/converters:** recommended next proof within existing feature/data/provider constraints; size and quality benefits remain unproven and must include every resource.
- **Raise budgets:** requires a new explicit user agreement supported by full measurements. No target is changed here.
- **Remove pages/processing, require first-run downloads/developer runtimes, or move application data/backend to Dozu cloud:** conflicts with approved scope and is not proposed.
- **Replace UI/database/framework now:** not supported by this component evidence; would add compatibility work and is not justified by a model/runtime payload failure alone.

This draft records a falsified default footprint assumption and a bounded continuation plan. It deliberately does not certify full-stack startup, complete feature parity, minimum-hardware performance, release security, signing, upgrade/backup/uninstall or all-platform support.
