# Installed-resource and upgrade contract

**Current #38 scope:** Windows x64 only, per the user's 2026-11-14 instruction and [scope.json](../../resources/manifests/scope.json). Required native acceptance is Windows 10 22H2 and Windows 11. Generic Unix/macOS helper notes below describe retained mechanics, not current acceptance gates.

This is a build/verification helper and an integration contract, not an implemented updater or installer. #24/#28/#34/#23 own signed distribution, supervisor integration, final paths and installation. Final target records deliberately retain `installedResourceManifest: null` and `appDataSchemaRange: null`.

## Controlled assembly

1. On the controlled build host, verify the checked-in artifact/wheel/model hashes **before** extracting, installing or executing inputs. Acquire only exact versions; source/metadata pins alone cannot satisfy binary closure. Record resolved URLs, byte hashes, compiler/SDK/OS/CPU flags, build source commit and lock hashes. Verify upstream signatures independently where supplied. Node OpenPGP, Python signed source and EDB independent archive identity still need review; TLS plus a computed digest is recorded honestly.
2. Build the complete production frontend/API closure with the target toolchain, including standalone traced server files, `.next/static`, `public`, generated fonts and local PDF workers. Preserve all routes. Generate target production dependency inventory from the frozen lock and actual output, retain all dependency licenses/notices, and inspect every `.node` and linked native library. Build tools/dev dependencies/caches and registry configuration stay outside the release stage. Disable dependency/browser/model acquisition in end-user startup; resolve retained external APIs only when the real feature needs them.
3. Stage explicit reviewed resources in a fresh immutable release tree, separate from accounts, DB/WAL, Redis persistence, files, jobs, secrets, logs, caches and backups. Do not copy a checkout or a developer home. Review secret scanning and staged file list as well as the path denylist; arbitrary credentials inside innocently named files cannot be disproved by filename filtering. Exclude dotenv, private keys, package registry config, caches and user state. Never require npm/pip/apt/brew/Docker/WSL on the target. The Node component example contains `node.exe` and LICENSE only.
4. Generate an inventory **outside** the immutable root using a reviewed spec: `{"target":"win32-x64","resourceSet":"<release ID>","approvedRoots":["runtimes","app","model","notices"]}`. Each listed root/file must exist; other payloads fail. Paths are relative, contained, unique ignoring case; absolute/escaping/dangling links fail. Internal relative framework links are represented without traversal and require native macOS signing verification. File sizes/SHA256, exact directories/link targets and native Unix executable bits are recorded. Rebuilding from Windows does not certify Unix modes.
5. Bind the final inventory hash, target and release ID to a signed package/envelope and trusted supervisor. Review signing transformations: generate the final file inventory after inner code signing and verify it after outer packaging. Signatures, app entitlement/fuses and code-loading policy must prevent replacement of both code and trust metadata. Do not treat the CLI's caller-supplied digest as independently trusted. No self-referential manifest hash is required.

```powershell
node tooling/resource-integrity.cjs create <immutable-root> <inventory-outside-root.json> <reviewed-spec.json>
node tooling/resource-integrity.cjs verify <immutable-root> <inventory.json> <trusted-SHA256> win32-x64 <release-ID>
```

## Launch and integrity failure

The integrated supervisor must verify the authenticated inventory and expected compatibility before starting any managed executable/importing native code. Reject missing, changed or extra resources and wrong target/release IDs. Explain repair/reinstall using a trusted offline installer; never download a replacement silently or continue with a Hub/CDN/host-runtime fallback. Do not delete or rewrite user data on failure. Model startup already verifies its own backend-specific files; the complete installed-root gate is additional.

This helper assumes a protected, quiescent resource tree. It is not a defense against concurrent filesystem replacement by an actor who can modify trusted installation files. #34 must prove ACL/ownership, canonical paths and the verification-to-execution boundary. Read-only installation, macOS framework links/native modes and signature integration remain unpassed; current checks are on Windows developer-host fixtures.

## Compatibility and activation

- Resource schema version 1 identifies the inventory format. A release ID identifies the complete immutable set; never mix Electron/Node/native modules/model files from different sets. Build API/Next native dependencies for standalone Node, not Electron's ABI. Run actual production imports on each native baseline after any runtime/dependency change.
- PostgreSQL candidate major is 17. Pin all tools to the same distribution and record cluster format, locale/ICU/collation/config and permitted application schema range. Minor-update compatibility does not waive actual extension/locale/reindex/library tests. Major updates require a separately validated `pg_upgrade` or dump/restore with matching old/new tools and consistent backup. Do not start an old binary on an upgraded cluster. #29 owns relational migrations, including the pgvector-free retained embedding path.
- Redis binaries must prove existing BullMQ/Lua/pubsub/counter semantics and AOF/RDB compatibility, including interrupted writes and restoration. Do not run incompatible older binaries against newer persistence. Flush-and-recreate is not acceptable for durable jobs/state; do not revive the Redis-removal proposal.
- Embedding compatibility key: exact MiniLM revision, tokenizer/config, 128-token truncation, mean pooling, normalization, dimension 384 and backend representation. Preserve the pinned CPU baseline. Model/backend/quantization changes require validated reindex/migration/versioned vector storage; do not silently combine FP32 and ONNX vectors because their dimensions match. ONNX remains optional evaluation.
- Stop owned processes cleanly, calculate actual free space for new/old resources, DB backups/migration and user data, verify all staged bytes, then activate the whole set atomically where possible. Preserve the last compatible resource set and backup. If migration fails, restore the matched data snapshot before reverting binaries. Never roll binaries back independently after destructive schema/format changes. Offline manual signed updates must work; startup/local data access cannot require an update server.
- Verify paths containing spaces/Unicode and read-only installation; processes write only to approved mutable roots. Prove interrupted update/restart, corrupt/missing resources, downgrade rejection, backup/restore and uninstall keep/delete on every native baseline. Accepted 10 GB free/3 GB installed limits do not replace per-update disk calculation. No update/lifecycle AC is passed by defining this contract.
